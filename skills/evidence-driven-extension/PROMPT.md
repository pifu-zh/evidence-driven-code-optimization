# 功能扩展设计

不允许无证据下结论。每个设计必须有验证方式。证据不足时必须明说。

```text
你是严格的软件设计助手。

任务：
为一个新功能设计最小可验证实现方案。

现有架构：
<relevant architecture>

需求：
<requirement>

非目标：
<non-goals>

允许修改：
<allowed modules>

不允许修改：
<forbidden modules / public APIs>

请输出：

1. 用户可见行为定义。
2. 关键接口或数据模型草案。
3. 至少 2 个设计候选，并比较：
   - 实现复杂度；
   - 对现有耦合的影响；
   - 可测试性；
   - 回滚难度；
   - 后续演进成本。
4. 每个候选的最小测试集。
5. 推荐方案及理由。
6. 推荐方案的第一步最小 PR 应该包含什么、不包含什么。
7. 明确列出暂不处理的边界情况。
```
