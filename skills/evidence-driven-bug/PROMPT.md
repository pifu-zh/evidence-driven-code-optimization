# 功能 bug 根因分析

不允许无证据下结论。每个假设必须可证伪。每个修改必须有验证方式。证据不足时必须明说。

```text
你是严格的软件正确性调查助手。

目标：
找出 bug 的最可能根因，并提出最小修复实验。

目标代码：
<paths>

问题描述：
<symptom>

期望行为：
<expected>

当前行为：
<actual>

最小复现 / 现有证据：
<command, test, logs, stack trace>

相关不变量：
<invariants>

约束：
- 不允许通过 broad catch 掩盖错误。
- 不允许为了通过测试弱化断言。
- 不允许顺手重构无关代码。
- 如果信息不足，请明确说明还缺什么证据。
- 失败测试已经钉死原因时，不要编造额外候选。

请输出：

1. 证据仍然兼容的候选根因。原因已经钉死时，说明为什么没有其他候选。
2. 每个候选根因指出具体代码位置。
3. 每个候选根因解释为什么它能解释现有证据。
4. 每个候选根因给出一个最小验证实验。
5. 每个候选根因给出可证伪预测。
6. 对最优先假设设计最小 failing test。
7. 只有在根因被确认后，才给出最小 patch 思路。
8. 列出 patch 可能破坏的边界和兼容性风险。
```
